{# Reusable KinJo logo component. Usage: {% from 'components/kinjo_logo.html' import kinjo_logo %} {{ kinjo_logo(size='navbar') }} size values: navbar — top nav / admin header (height follows --admin-header-height) sidebar — sidebar header (width: 120px, height auto) login — login brand panel (height: 160px, width auto) Every here previously opened with `width=" 60\ height=\60\`, an unterminated attribute that swallowed the next line. An HTML parser resolved it to width=' 60\ height=0 src=' plus three junk attributes named `static`, `img` and `kinjo-logo.png"` — and, critically, **no src at all**. No amount of CSS can size an image the browser never loaded, which is why repeated attempts to set the height appeared to do nothing. Sizing lives in CSS, never in a style attribute. An inline style beats every stylesheet rule, which is what forced the escalating !important overrides. Class-only markup lets ordinary specificity work. The width/height attributes are intrinsic-ratio hints so the browser reserves space before the image loads (no layout shift). They describe the rendered box, not the artwork: the navbar box is 74x64 — header height, widened by 10px — while the square artwork inside it stays undistorted via object-fit: contain. Asset: kinjo-logo-320.png is a 320x320 palette PNG — 49 KB against the 997 KB 1254x1254 original, which was being downloaded on every admin page to be drawn at 64px. 320px still covers the largest use (login, 160px) at 2x device pixel ratio. alt is intentionally empty: every call site wraps this in an that already carries an aria-label, so alt text here would make a screen reader announce the brand twice. #} {%- macro kinjo_logo(size='navbar', extra_class='') -%} {%- if size == 'sidebar' -%} {%- elif size == 'login' -%} {%- else -%}{# navbar / admin header #} {%- endif -%} {%- endmacro -%}
